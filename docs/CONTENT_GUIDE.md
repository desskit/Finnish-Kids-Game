# Content guide — growing the learning path

This is the practical guide for adding content to Kielipesä. The app is organized
as a **journey path** of chapters → skill nodes (see `src/game/path.tsx`), built
around *usable Finnish* (things you can say). Vocabulary is the material that
flows through the communicative skills.

## The one golden rule

**Never generate or inflect Finnish in code.** Every Finnish form shown to a
child is *looked up* from human-sourced, tagged data (Wiktionary via kaikki.org,
CC BY-SA 4.0). If a word form you need isn't in the data, the word can't be used
until the form is added to the source. This is what keeps the Finnish correct
(consonant gradation, agreement, rection, …).

So adding content is usually two steps: **(1)** make sure the words exist in the
sourced data, then **(2)** wire them into a construction / skill / sentence.

### Hand-written Finnish goes to the native review

Some Finnish can't be looked up: stories, scene lines, carrier frames, the
forms a pattern marks wrong, lesson quotes, titles, and the screens' own labels
("Jatka", "Mitä kuulit?"). All of it is listed in ONE place,
`src/game/reviewEntries.ts`, under stable keys. That list feeds both
`docs/FINNISH_REVIEW.md` and the in-app review (Grown-ups → Finnish check),
where a Finnish speaker marks each entry ✓ correct or ✎ needs a fix.

- Run `npm run review:content` after adding authored Finnish. It first pulls
  the screen labels out of the components (`data/ui-finnish.json`, via
  `src/test/uiFinnish.ts`), then rewrites the review sheet. A test fails if the
  labels file is out of date.
- Tests check that every authored word is a real form: stories, scenes,
  titles and labels are all checked against the vendored tables. A real word
  the tables lack must be listed with its meaning.
- The reviewer's downloaded file is merged with
  `npm run review:import <file>.json`:
  - approvals go into `data/finnish-vetted.json`;
  - fixes go into `data/finnish-flags.json`, shown as 🚩 in the sheet.
- An approval holds only while the text reads the same. Change the Finnish and
  it needs checking again.
- **Checked against Wiktionary** (`data/finnish-wiktionary-checked.json`, 📖):
  entries short enough for a dictionary to settle were checked by hand
  against English Wiktionary (read through kaikki.org), so the native reviewer
  doesn't have to. That covers single words and forms, lists of forms, the
  letter names, the "Do you…?" questions (the verb's 2nd person present plus
  *-ko* / *-kö*), and short titles, labels, lesson quotes and sentence patterns
  whose every word is a Wiktionary form in the grammar used, built the plain
  textbook way. Each entry keeps its Finnish as checked and a line of evidence,
  which names the reading the app uses — *uusi* is "new", not the past of
  *uusia*; *en ole* is the connegative, not the imperative *ole*. Change the
  Finnish and it goes back to "to check" (a test fails until the
  ledger is updated or the key dropped). Stories, scenes, the forms marked
  wrong, the wrong replies, math frames and made-up compounds stay with the
  native reviewer; `notes` says why a dictionary couldn't settle an entry. A
  reviewer's own ✓ or ✎ always wins.
- Quote **Finnish** in lesson prose with `*single asterisks*` (the lesson shows
  it in the Finnish style, and the review lists it). Put English examples in
  "quotes" or **bold**, never in single asterisks.

## 1. Add vocabulary (words)

Words live in `src/content/data/*.sourced.json`, generated by the curation
script from the vendored dataset.

1. Edit the curation lists (`ANIMALS`, `FOOD`, `FAMILY`, `NUMBERS`, `PLACES`,
   `BODY`, `NATURE`, `CLOTHES`, `ADJECTIVES`, `VERBS`) in
   `scripts/build-kids-data.mjs` — add the word's lemma + English gloss
   (+ an emoji until art lands). Keep ids globally unique across themes (the
   content-integrity test enforces this) and avoid plurale-tantum nouns like
   `housut` — they lack the singular case forms the carrier phrases need.
2. Regenerate:
   ```bash
   node scripts/build-kids-data.mjs data/finnish-inflection-drill
   ```
   This copies the verified inflection table + tags into the `*.sourced.json`.
3. If the word isn't in the upstream dataset, it must be added there first (see
   `data/finnish-inflection-drill/README.md`). Don't hand-type inflections.
4. `npm run test:unit` — the content-integrity test (`src/content/content.test.ts`)
   checks ids are unique and every construction can be filled.

New words automatically join the mixed noun pool the path's skills draw from, and
the spaced-repetition Review.

**Semantic tags.** A word can carry hand-curated `tags` that decide which
carrier phrases make *sense* for it (beyond grammar). Today places carry a
locative-shape tag — `'surface'` (you sit ON it), `'container'` (you go IN it),
or both — set in the `PLACE_TAGS` map in `scripts/build-kids-data.mjs`. The
locative carriers require the matching tag (`requiresTags` in
`src/content/constructions.ts`), so a flat `table` never gets an "in the table"
question and a `car` (tagged both) plays in every "where" case. Add a new place
to `PLACE_TAGS` when you add it, or the content-integrity test will flag it.

## 2. Add a carrier phrase (single-slot construction)

A `Construction` (`src/content/constructions.ts`) is a phrase with **one**
inflected slot, e.g. `Tämä on ___`. Add an entry with the fixed words + the
`case` + `number` the slot must take (the form is looked up by those tags):

```ts
{ id: 'i-want', before: 'Haluan', punct: '.', en: 'I want a ___.',
  tier: 3, case: 'partitive', number: 'singular' }
```

Then expose it as a skill (step 4). Make sure the chosen case exists for the words
you'll use (the integrity test will catch gaps for the noun topics).

See `docs/FINNISH_GRAMMAR.md` for which case/number a construction needs for
possession, negation, partitive-government verbs and counting — it's the
authoring contract behind the `case`/`number` tags above.

## 3. Add a skill node / chapter (the path)

The path is data in `src/game/path.tsx`. A **skill node** picks an existing game
(`activity`) + a content scope:

```ts
{ id: 'i-want', titleFi: 'Haluan…', titleEn: 'I want…', icon: '🙋',
  activity: 'build', content: { constructionIds: ['i-want'] }, exampleFi: 'Haluan omenaa.' }
```

- `activity`: `listen | build | count | match | conjugate | order | spell | sentence | review`
- `content.pool`: which words — `'nouns'` (all noun topics mixed, default),
  `'animals' | 'food' | 'family' | 'numbers' | 'places' | 'body' | 'nature' | 'clothes'`,
  `'verbs'` (the emoji-bearing action verbs, for picture-card games),
  `'money'` (the euro, for counting prices: *kaksi euroa*), `'meals'`
  (breakfast, lunch, dinner, the evening snack: *Syön aamupalaa*), or
  `'mixed'` (every word, nouns and verbs alike — for a words step whose
  `only` list holds both, like *rakastaa* beside the Likes unit's things).
  The money, meals, weather and Finnish-year topics are opt-in like days
  and numbers, so *euro*, *aamupala*, *sää* or *joulu* fills no carrier
  phrase unless one names it (*Odotan joulua!* names the Finnish year).
- `content.constructionIds`: for `build`/`order`, which carrier phrases to drill
  (omit = all).

Add it to a chapter's `skills`, or add a whole new `Chapter` (give it a `titleFi/En`,
an `accent` color, an `icon`). No router or component changes are needed —
progress, adaptive difficulty, badges and the dashboard all pick it up by id.

## 4. Add a multi-slot sentence (the "Full sentences" chapter)

This is the advanced chapter — **wired but intentionally empty** today. Authoring
templates in `src/content/sentences.ts` makes playable nodes appear automatically
(`buildSentenceRound` turns each into a Word-Order round; see `src/game/round.ts`).

A `SentenceConstruction` is an ordered list of `tokens` (a fixed word or a `slot`)
plus the `slots` themselves. Each slot pulls a form from the data; **agreement is
resolved by copying tags** (never by rule):

```ts
// "Minä annan koiralle luun."  (subject + verb + recipient + object)
{
  id: 'give-recipient-object',
  en: 'I give the dog a bone.',
  tier: 4,
  punct: '.',
  tokens: [{ slot: 'subject' }, { slot: 'verb' }, { slot: 'recipient' }, { slot: 'object' }],
  slots: [
    { id: 'subject',   role: 'pronoun', fixedId: '1sg' },
    { id: 'verb',      role: 'verb', verbSlotForm: 'conjugated',
      tense: 'present', polarity: 'positive', agreesWith: 'subject', fixedId: 'antaa' },
    { id: 'recipient', role: 'noun', case: 'allative', number: 'singular', pool: 'nouns' },
    { id: 'object',    role: 'noun', case: 'genitive', number: 'singular', pool: 'nouns' },
  ],
}
```

Patterns this supports:
- **Two objects / recipient + object** — two `noun` slots in different cases.
- **Adjective + noun object** — an `adjective` slot with `agreesWith` its noun slot
  (it copies the noun's case + number): `Näen ison koiran`.
- **Verb chains (multiple verbs)** — one `verb` slot `conjugated`, another with
  `verbSlotForm: 'infinitive'`: `Haluan syödä omenan`.

Slot fields: `role` (`noun|adjective|verb|pronoun|number`), `case` + `number`
(nouns/adjectives), `tense` + `polarity` + `verbSlotForm` (verbs), `agreesWith`
(another slot id), `pool` (draw a random word) or `fixedId` (pin one word/pronoun).
Pronoun ids are `1sg,2sg,3sg,1pl,2pl,3pl`.

Tips: pin words with `fixedId` while drafting so you can read the exact sentence;
the resolver returns nothing for a slot whose form is missing in the data (so make
sure the needed case/conjugation exists). The shape is **v1** — expect it to gain
fields (optional slots, alternate word orders) as real templates arrive.

## 5. Pictures

Content still names its pictures by emoji (a word's `emoji`, a story's `fg`, an
answer's picture), and the app draws each as its picture from the pixel-art
set. How the set works, and how to add a picture, is in
[`docs/ART_GUIDE.md`](ART_GUIDE.md).

- **A new emoji needs its picture first.** `src/art/coverage.test.ts` fails
  for an emoji in the content or the code that has no picture. Without one,
  the app shows nothing in its place, never the emoji itself.
- **A new word with an emoji** gets a word picture with the word's id.
  Something a story shows that isn't a word is a story prop
  (`art/recipes/props.mjs`).
- **Numbers and keycaps** (`3️⃣`, `11`, `1.`) need no picture: they sit on the
  number tile.
- **A word draws its own picture.** A word with its own picture uses an emoji
  no other word's picture has (`coverage.test.ts`): "Syö!" must show eating,
  not the table that once shared 🍽️ with it.
- **Look-alikes never share a question.** A listening card shows only the
  picture, so two that a child can't tell apart (son, brother and child; soup
  and porridge; draw and paint; smile and laugh) are never offered side by side.
  `NEVER_TOGETHER` in `src/content/apart.ts` lists these groups, and every game
  that offers pictures keeps them apart (`apart.test.ts` sweeps them all). A
  new word that looks like, or means nearly the same as, another goes into a
  group there.
- **Per-chapter color:** change a chapter's `accent`. It themes the band, the
  node rings and the "next" highlight.

## The guided course: units, lessons, "Why?" tips

The home screen is a **course of units** (`src/game/path.tsx`, `UNITS`), not an
open map. Each unit is one idea a beginner can hold, met in the order
**hear it, use it, notice it** (docs/LEARNING_RESEARCH.md — young children
learn a pattern from input first, and a rule helps only once they've met it):

1. **Kuuntele ensin** (listen first) — the unit's story, heard page by page
   with its pictures before any practice: no questions, no score
   (`/opener/:unitId`). The story is the unit's `<unit>-story` step, or its
   story step with stories of its own;
2. the **first practice step** — the new phrases modelled, then used;
3. the short **lesson** (`src/content/lessons.ts`) — 4–8 cards with 2–3 "try
   it" checks, after that first step. A younger reader sees its **notice
   cards** (`noticeCardIndexes`: one short explain card, the first examples
   and the first check — at most three, no grammar terms; a lesson can pick
   its own with `notice`). The Notebook always has the whole lesson;
4. the rest of the practice **steps** (part-way lessons as before), then the
   story again, now with its questions;
5. a **checkpoint** (`/checkpoint/:unitId`) that unlocks the next unit.

The rules (unlocking, "done", Continue) live in `src/game/course.ts`. A unit
begun any other way (an older save that read the lesson first, or a step
played) counts its opener as heard, so no child is sent backwards.

**Who's reading** (`src/game/learner.ts`): each player is a younger reader
(about 6–7) or an older one (about 8–10), set by a grown-up. Younger readers
hear explanations read aloud and English prompts on a step's first level;
older readers read them. Write lesson prose that works read aloud: short
sentences, Finnish quotes in `*single asterisks*` (read in the Finnish voice).
**English help** (Grown-ups → Settings) fades the English beside scene and
dialogue lines after a step's first level by default; the drills' own tasks
stay in English.

**Bonus steps** (`optional: true` — the Finnish-sounds steps, `SOUND_STEPS` in
`path.tsx`): Continue offers one once, but it's never part of the checkpoint
and never holds the unit back, because it needs a Finnish voice to be heard.

**Syllables** for younger readers come only from Wiktionary
(`data/wiktionary/hyphenation.json`, refreshed with
`node scripts/fetch-hyphenation.mjs <words.json>`). A new word missing there is
shown whole — never split by rule.

### Adding or changing a unit

- `newWords`: the item ids the unit introduces. Each word may be introduced
  only once in the course. Steps draw from the unit's own words
  (`content.words: 'new'`, used by the "New words" warm-up) or, by default,
  from every word met so far (`'known'`).
- Unit ids are **semantic** (`having`, `when`, `town`…), never numbered, so a
  new unit can be inserted without renaming saved progress. "Unit N" on screen
  comes from position.
- Steps: use `phraseStep(...)` for carrier-phrase drills, `wordsStep(...)` for
  the vocab warm-up, `sceneStep(...)` for the unit's conversation,
  `reviewStep(unitId)` for a Kertaus, or a plain `SkillNode`. Dialogue, scene
  and story steps take `content.ids` to pick registry entries.
- **Build and order before done; typing is a minor extra.** `phraseStep`
  ramps `build → order → order` (top level 3). From `TYPING_FROM_UNIT`
  (Describing) on, sentence steps also get `minor: spell`: from level 2, one
  round in four asks the child to type the sentence. Minor rounds earn stars
  and count toward the Writer achievement, but never move the level or decide
  "done" (`ActivityProgress.bonus`) — a small challenge, never a roadblock.
- `checkpoint` (optional `ActivityKind`) is the game a step plays in its
  unit's checkpoint. `phraseStep` uses `order` and `wordsStep` uses `name`;
  without it the checkpoint uses the step's top game at its done level.
- **One conversation per unit.** Every grammar unit ends with a
  `sceneStep` whose 3-turn scene (`src/content/conversations.ts`) uses only
  that unit's grammar and the words met so far. Distractors are real Finnish
  that is the wrong move — ideally the unit's own contrast ("Olen puistossa"
  for *Mihin menet?*). New scenes are ⚠️-flagged for native vetting.
- **Only one right reply.** The reply games fill their options with other
  exchanges' replies. Where one of those fits a prompt too ("Kiitos!" to
  *Hyvää ruokahalua!*, "Pitsa." to *Mikä tämä on?*), add it to the prompt's
  `alsoFits` in `dialogues.ts`, and it's never offered there as a wrong one.
  Options are compared as heard, so "Ole hyvä!" and "Ole hyvä." never both
  show.
- **Kertaus (mixed review).** `reviewStep(unitId)` creates a step with
  `content.mix`. The course resolves it to `content.mixOf`: every *mixable*
  step of the EARLIER units (phrase, conjugation, count, match, possessive —
  not words, dialogue, scene or story steps). Each segment plays one of them
  (`mixStepFor`, a coprime stride, so a session rotates through different
  ones) with that step's own scoping, pin and game, while progress records
  under the Kertaus step. They sit in units 5, 10, 15 and 20.
- **"Muistatko?" in checkpoints.** From unit 3 on, `checkpointPlan` adds a
  2-question part from one earlier unit's step, picked from the attempt count,
  so a retry asks about something different.
- Every unit but Mestari pins `maxTier` to 10 automatically, because a step's
  constructions are already exactly what its lesson taught. A conjugation step
  also pins `verbCombos` to its lesson's tense. Only Mestari (the last unit)
  is unpinned, so its original deep ladders climb to L9–10.
- **A step is done only when its TOP level is proven.** The child reaches the
  step's `maxLevel`, then clears the same bar a promotion would need there
  (`provesTop`: enough rounds, a high enough first-try average). That is
  recorded as `topProvenAt` and stays set. Every game on the step's ladder is
  unlocked by its top level, so none can be skipped (a test enforces this).
  Choose `maxLevel` with that in mind: a single scripted scene uses 2, words
  use 3, sentences use 4. Checkpoints ask at each step's top level.
- **Words without a picture** (days, *janoinen*, *olohuone*…) are fine in the
  words step: Listen-and-tap shows the English word on the card, Name-it
  prompts with the English word, and Build shows the gloss. Only count, match
  and yes/no need a picture, and they filter those words out.

### Choose-the-form steps (`activity: 'choose'`)

`src/game/formChoice.ts` + `ChooseForm.tsx`: the options are the SAME word(s)
in several real forms, and the child picks the one this moment needs. Set
`content.choose` to:

- `answer` — *Syötkö?* → *Syön.* / *En syö.* (not *Syöt.*)
- `ask` — "Do you sleep?" → *Nukutko?*
- `mood` — *Juokse! / Älä juokse! / Juostaan!*
- `pronoun` — *Auta minua! / Anna se minulle! / Pidän sinusta.*
- `owner` — *isän pyörä* (not *isä pyörä*)
- `verb-type` — *laulaa* → "Tyyppi 1" (filter the step with `content.verbs.types`)
- `degree` — "bigger" → *isompi* (not *iso*, *isoin*)
- `compare` — *Kumpi on isompi?* → *Norsu on isompi kuin hiiri.* (not the reverse)
- `superlative` — *Mikä on isoin?* → *Norsu on isoin.*
- `ordinal` — "the 3rd" → *kolmas* (not *kolme*)
- `date` — "May 5th" → *viides toukokuuta* (not *viisi toukokuuta*, *viides toukokuu*)
- `age` — "I'm 8" → *Olen kahdeksan vuotta vanha.*

Verb forms come from the sourced tables (the build keeps the "don't" and
"let's" forms too). Two small closed sets are hand-authored and pinned by
tests: `questions.ts` (*syötkö* = sourced *syöt* + -kö, checked by vowel
harmony) and `pronouns.ts` (*minua, minulle…* — the vendored data has no
pronoun paradigm).

### Verb types, KPT and lessons part-way through a unit

- `src/content/verbTypes.ts` gives a verb's school type (1–6) from its SOURCED
  Kotus class, and finds consonant gradation (KPT) by comparing the sourced
  infinitive with the sourced *minä* form (*nukkua → nukun*). Nothing is built:
  the KPT test only compares, and `markGradation` only marks letters.
- A conjugate or choose step narrows its verbs with
  `content.verbs: { types: [1, 3], kpt: true }`, or names them with
  `content.verbs: { ids: ['play', 'play-game', 'play-music'] }`.
- `Chapter.midLessons: [{ lessonId, before }]` puts a lesson PART-WAY through a
  unit. It opens once the steps before `before` are done, and the steps from
  `before` on wait until it's read. Words listed in a later words step's
  `content.only` stay out of every step before the lesson. That's how the
  verbs units bring in their KPT verbs halfway. A unit can have several: each
  lesson holds back its own words, so The Finnish year's winter steps never
  meet Easter's words, nor its Easter steps Midsummer's.
- `wordsStep(unit, pool, title, only, id)` meets only part of a unit's words.

### Comparisons and dates (`compare.ts`, `dates.ts`)

Adjective degrees (*isompi*, *isoin*, *parempi*, *paras*) are their own
dictionary headwords in the source, and the build attaches them as
`item.degrees`. `RANKINGS` in `compare.ts` is authored WORLD KNOWLEDGE, as item
ids: which thing really is bigger, faster or older. Only well-separated pairs
are ever compared, so a sentence is always true. A date is the sourced ordinal
plus the sourced month partitive (*viides toukokuuta*). Only 1st–10th are
sourced ordinals, so dates stop at the 10th. The glue patterns are listed in
`FINNISH_REVIEW.md` under "Comparison & date patterns".

### Verb carriers (`verb: 'infinitive'`)

*Haluan ___.*, *En halua ___.*, *Osaan ___.*, *Saanko ___?* take a VERB in its
dictionary form (the sourced infinitive). Use `topics: ['verbs']` plus an
`onlyIds` list of verbs that read naturally.

### Feelings that happen to you (`verb: 'impersonal'`)

*Minua pelottaa* is "it scares me": *minua* plus the verb's sourced "it" form
(present 3sg). The five feeling verbs (*pelottaa, jännittää, väsyttää,
naurattaa, itkettää*) are their own theme, `feelingVerbs`, with the topic
`feeling-verbs`: they're never conjugated in the verb games (the verb pool
doesn't hold them), and only a carrier with `verb: 'impersonal'` and
`topics: ['feeling-verbs']` takes them. Their slips are the "I" and "you"
forms (*Minua pelotan*), which are wrong in every reading.

### A slot that starts the sentence

A carrier with no `before` and a `punct` starts with its slot, and the slot's
form is capitalized: *Aurinko paistaa.* (`sentenceWithForm`; the listening
games' carrier text does the same).

### Which play? (`choose: 'play'`)

English has one "play"; Finnish has three: *leikkiä* + **-lla** for toys
(*Leikin nukella*), *pelata* + **-a** for games and sports (*Pelaan
jalkapalloa*), *soittaa* + **-a** for music (*Soitan pianoa*). The choose
game asks which, over the step's three frames (`play-with-toy`,
`i-play-game`, `i-play-music`). The wrong options are the other verbs with
their **-a** — but *leikkiä* is never offered as wrong for a ball or an
instrument (*Leikin pallolla*, *Leikin rummulla* are right Finnish), a ball
is never asked about (*Pelaan palloa* is right too), and a toy's second wrong
option is the ending slip, since *Soitan lelua* can be said of a musical toy.

### Kapteeni käskee (`activity: 'captain'`)

The captain game plays in the listening-sentence screen. `buildCaptainRound`
mixes body commands from the step's carriers (*Kosketa nenää!*, *Nosta käsi
ylös!*) with the actable verb commands (*Hyppää!*), and says each as *Kapteeni
käskee: …*. From four tiles on, the last tile is the captain's **Ei!** and
about one command in three comes without *Kapteeni käskee* — then **Ei!** is
the right answer, and a right tap credits no word (`attemptId: null`). The
body carriers only take what a child can do: never touch an eye, a tooth or
the tongue (`TOUCHABLE` in `constructions.ts`).

### Carrier options added for the expansion

- `possessor` (`'1sg' | '2sg' | '3rd'`) makes `formFor` return the sourced
  possessive form: *Tämä on minun **kirjani**.* Form tiles and "Why?" tips
  follow it.
- `glossById` overrides the English for one word when the literal reading is
  wrong: *Minulla on nälkä* → "I'm hungry", not "I have a hunger";
  *Leikin yöllä* → "I play at night"; *Kello on puoli kahdeksan* → "It's
  seven thirty".
- `pictureById` shows a picture of the phrase's own for a word: the clock
  phrases show the clock face (*Kello on puoli kahdeksan* shows half past
  seven, not the number 8), *Sataa vettä* shows the rain. Every place that
  pictures a word in a phrase goes through `pictureFor(item, construction)`.
- `onlyIds` / `topics`: **days, seasons, feelings-as-nouns, adjectives and
  numbers are opt-in.** A carrier only takes them if it names their topic or
  id, so "Minulla on maanantai" can't be assembled. The one exception is a
  thing-describing adjective after *Tämä on / Onko tämä* ("Tämä on
  punainen."); feelings never go there, because they need a living subject.
- **Person locatives** (*Olen / Menen / Tulen* + place) take only places
  tagged `person-in` or `person-on` in `scripts/build-kids-data.mjs`, so a
  child goes *puistoon* and *asemalle*, but never "Olen pöydällä".
- Run `npx vitest run src/game/course.viability.test.tsx`. It renders every
  step × game × level and fails if any step can't fill a real question (too
  few known words, places without the right tags, …).

### Nothing sad or unkind

A child builds these sentences about themselves, so the generated ones never
make them say something hurtful or sad: never that they have no mom, dad,
grandparent, family or friend (`NOT_TO_DENY` in `constructions.ts`), never
that they don't like a person (the dislikes skip `PEOPLE`), and never that
they own a baby, a child or the sun. The example sentences from Tatoeba are
shown only once a person has approved them (`APPROVED` in `examples.ts`).

### The English side

The English a child reads is assembled too, so it follows a few rules
(`englishSentenceFor` and its helpers in `src/content/types.ts`). The app
writes **US English**: Mom, candy, soccer, cafeteria, "Do you have…?".

- **Family by name, relatives as "my":** Mom, Dad, Grandma, Grandpa
  (`FAMILY_NAMES`); brother, sister, friend, aunt, uncle, cousin, son,
  daughter and grandchild are "my ___" (`MY_PEOPLE`): "I see my aunt",
  "Where are my cousins?".
- **Liking a food is liking the kind:** *Pidän omenasta* → "I like apples".
  Mass foods and one-dish foods (`LIKED_AS_A_KIND` in `semantics.ts`) take no
  article: "I love pizza". Animals and things keep "the": "I like the cat".
- **Plurals and counting** go through `pluralEn` / `countedEn`: the sourced
  plural, except words English counts in pieces ("loaves of bread", "1
  homework task", "sheets of paper").
- **One word reads oddly in one carrier?** Use that carrier's `glossById`
  ("I don't have any candy") or `sentenceById` ("I'm watching soccer."). If
  the Finnish itself is odd for a word ("Odotan vauvaa" means expecting a
  baby), gate the word out with `excludeIds` instead.
- **Second meanings** (`ALSO_EN`): *poika* is "son, boy", *kynä* "pencil,
  pen". They show on the new-word card and in the story glossary.
- **A label's English is what its Finnish means.** A child learns from the
  pair, so *Mitä pitää tehdä?* is "What do you have to do?", never "Tap what
  the command says". An extra hint can follow a dash ("Listen first — then
  it's your turn").
- **A prompt shows the sentence the voice reads**: "This is my brother.",
  not the carrier's "This is a ___." beside "brother".
- **Real example sentences** (the "Lue lause" game) come from Tatoeba but show
  only when listed in `APPROVED` in `src/content/examples.ts`, after a person
  has read them. Leave out a word used in another sense, spoken forms (*mä,
  haluun*), sayings, and any whose English doesn't say what the Finnish says.
- `src/content/english.test.ts` pins these rules. Before a release, re-read
  `docs/SENTENCE_AUDIT.md` (`npm run audit:sentences`), which lists every
  carrier sentence with its English.

### Writing a story (`unitStories.ts`, `stories.ts`)

A story is a little picture book: a cover, three or four pages, "Loppu!", then
questions about what happened. It is read for meaning, once — not drilled.

- **Write it with the kit** (`src/content/storyKit.ts`): `page(sc(setting, who),
  ...lines)`, `tell(fi, en)` for narration, `say(castId, fi, en)` for a
  character talking (a speech bubble, in their voice), `ask(...)` with
  `right(...)` / `wrong(...)` for picture questions, and `trueFact` /
  `falseFact` for true-or-false statements.
- **The same people every time** (`CAST`): Aino (the main character, and the
  teller of first-person stories: `narrator: 'aino'`), her friend Eero, Äiti,
  Isä, Isoäiti, Aino's cat Mirri, Eero's dog Musti, the teacher, and Leo —
  and once a year Joulupukki. Each has a speech pitch, so they sound
  different with the one Finnish voice. Those called by a word, not a name
  (Äiti, Isä, Isoäiti, Opettaja, Joulupukki: `CALLED_BY_A_WORD`), show their
  word when tapped in a story (*äidille* → to Mom).
- **Something happens.** Someone wants something, something goes wrong or
  surprises, and it ends — not a list of sentences. Three or four pages, one to
  three short lines each (at most six or seven words), each page a scene: its
  setting, one of the drawn backdrops (`home`, `kitchen`, `bedroom`, `bathroom`, `party`,
  `christmas`, `classroom`, `library`, `shop`, `cafe`, `park`, `playground`, `yard`,
  `field`, `beach`, `bus-stop`, `zoo`, `forest`, `station`, `cottage`, `sauna`), who and what stand in
  front (`fg`, a few emoji, each shown as its picture), and a `tone` only when
  it isn't the usual one (inside for rooms, day outdoors): morning, evening,
  night, rain or snow. A setting comes only in the tones it's drawn in
  (`stories.test.ts` checks); a new setting or tone is a new backdrop in
  `art/scenes/`. Something in front that isn't a word needs a story prop
  (`art/recipes/props.mjs`).
- **The picture agrees with the text** (`stories.test.ts` checks): everyone
  who speaks on a page is in its `fg`; a page that says *Huomenta* is in the
  morning, *Hyvää yötä* at night, *Sataa lunta* in the snow and any other
  *sataa* in the rain; a page
  stays in one place. Check a new story on its storyboard too: the backdrop,
  the time of day and who's there.
- **Only the unit's grammar and the words met by then.** Every word must be a
  real form (`unitStories.test.ts` checks them all, titles and questions
  included); a name's case forms go in the lexicon's name list.
- **Questions — a bank, not a fixed quiz.** At least three picture questions,
  each with exactly one right answer that the story itself says, and (from
  unit 2) two or three true-or-false statements, both kinds, whose truth
  doesn't change during the story. Watch for things that change hands: if
  Grandma's ball is the children's by the last page, nothing may ask who has
  the ball. Each option's picture is different from the others', and a wrong
  option's picture is never a near-twin of the right one's (`stories.test.ts`;
  the cast's own pictures are exempt). "Put the pictures in order" and "Who says
  this?" are built from the pages (`src/game/storyQuiz.ts`) — a line that names
  its own speaker, or that two people say, is never asked. A read asks four, of
  mixed kinds; a re-read asks others.
- **Heard first, read last.** A unit's story opens the unit (heard with no
  questions) and comes back as its last step — so write it to be enjoyable
  before the unit's words are known: the pictures carry the meaning.
- **One good read finishes it** (`src/game/storyLog.ts`): 3 of 4 right first
  time. A weak read is read again with the English showing. After it's
  finished, a story comes back in the daily warm-up ("Muistatko?", two
  questions it hasn't asked) a day, three days and a week after its good read,
  and it waits on the Notebook's bookshelf.
- A unit's story step is made from `UNIT_STORY_IDS` (one story per unit); a
  step can also list several stories in `content.ids` (it is done once each
  has had a good read). New stories are ⚠️-flagged for native vetting and
  appear in the Finnish check under Stories.

### Writing a lesson

- The **prose is English**, written for a curious 8-year-old: short sentences,
  one idea per card, **bold** for the rule, *Finnish* in italics.
- **Every Finnish example is a reference, not typed text**: `{ word, case }`,
  `{ sentence: constructionId, word }`, `{ verb, tense, polarity, person }`,
  `{ possessive, possessor }`, `{ count, word }`, `{ agree, word, case }`, or
  a vetted dialogue line `{ line, part }`. These resolve through the sourced
  tables, and `lessons.test.ts` fails if any of them doesn't.
- The highlighter (`src/content/endings.ts`) only **marks** the ending of a
  looked-up form. If the form doesn't end in a known ending for its tag,
  nothing is marked.
- **Teach before you test.** Never ask for something the lesson hasn't shown:
  - Set phrases (greetings, "Ei se mitään") go in a `pairs` card, listed as
    **they say → you say back**. `lessons.test.ts` fails if a unit's dialogue
    step asks for a pair that its lesson never shows.
  - In the games, an exchange the child has never seen is **modelled first**
    ("Uusi fraasi!") and a never-heard scene plays as a full example ("Kuuntele
    ensin") before the child takes a turn. Both are remembered per child in
    `course.phrasesSeen`.
- A word brought in only to show a **sound** (*tulli* in the tuli / tuuli /
  tulli trio) lives in the lesson-only theme `lesson-words`. It is never in a
  game pool, and a check that uses it must be a **listening** check (`listen`:
  "which word do you hear?"), never "what does it mean?".
- Example rows for an inflected form need the English of the **phrase**
  (`en: 'on the table'`), not the bare word.
- Review every lesson as rendered with `npm run audit:lessons` →
  `docs/LESSON_AUDIT.md`.
- A `check` card has exactly one correct option. Wrong options may use
  `asCase` / `wrong` / `adjCase` to show a real form in the wrong place.
- Finnish quoted in prose (*minulla*, *edessä*…) appears in
  `docs/FINNISH_REVIEW.md` under "Lesson prose" for native vetting.

### "Why?" tips

`src/content/why.ts` holds the one-line rule shown after a wrong answer (per
construction, plus counting / verbs / possessives / agreement). The example
is the correct looked-up form with its ending marked. A new construction
should get a `CONSTRUCTION_RULES` entry; `why.test.ts` fails if it falls back
to the generic text.

## Achievements

`src/game/badges.ts` lists every achievement as a **measure** (`have / need`
plus a unit), and the Achievements screen (`/achievements`) shows exactly
what's left ("7 / 10 words"). To add one:

- Give it a category, a kid-readable `hintEn` saying exactly what to do, and a
  `measure(child, env)`.
- Measure only what is already stored (stars, SRS, `progress`, `course`,
  streaks). If it needs new facts about the content, add them to `badgeEnv`
  in `path.tsx`.
- Balance it against the current course. The early badges come in the first
  sessions; the course badges follow passed checkpoints; the skill badges
  reward the hard parts (typing, Kertaus, conversations), so nothing is worth
  skipping.

## Lasketaan! Math in Finnish (optional)

`/math` — a path beside the course, opened from the card under Continue on the
home screen. Math is done *in Finnish*: no digit is ever shown, so it can't be
done in English in your head.

- **The stages** (`src/game/mathPath.tsx`) are built like units: a lesson, a
  few games with levels, a story, and a test that wins the stage's crown. Every
  id starts `math-`. A stage opens once the one before has its crown (or the
  one it names, `afterStage`: the shop and the clock branch off after word
  problems) and the course has taught what it needs (`afterUnit`: euros, *My
  day*); the rules are in `src/game/mathCourse.ts`. Crowns, the quick-sums
  best run, spoken answers, today's sums and a worn face's animal live in
  `child.math`, never among the course's checkpoints, so math never moves
  "units done", Continue, the warm-up or a course badge.
- **The eight stages:** plus and minus to ten; more or less, before and after;
  word problems; the *-toista* numbers to twenty; the *-kymmentä* tens to
  *sata*; times tables and halves (*kertaa*, *puolet*); prices, totals and
  paying in coins (*euroa*, *yhteensä*); the clock an hour later or earlier, and
  half past (*tunnin päästä*, *puoli neljä*).
- **The problems** (`src/game/math.ts`, pure) use only sourced number words:
  *nolla* to *kaksikymmentä*, the round tens and *sata*. Compounds like 21
  aren't in the data and are never built, so every sum stays inside that set:
  times tables only where the answer is a word, halves of even wholes, prices
  of two euros or more (*kaksi euroa*), hours one to twelve.
- **The Finnish** is in `src/content/mathProblems.ts` (⚠️, in the Finnish
  check's Math section): each frame has its English for the reviewer only.
  The verb sets the math in a word problem (*saan* adds; *syön*, *annan* take
  away), and a frame only plays once the course has taught its verb. *yksi*
  never fills an object slot (it would be *yhden*).
- **No digits, anywhere.** Numbers are Finnish words and speech; an amount is
  dots in ten-frames (`Quantity`); a tapped number word shows its dots, never
  its English, and any other tapped word drops a bracketed example that holds
  a number (`mathGloss`: *puoli* is "half", not "… 7:30"); a level is dots, a
  score is stars. English lines keep numbers in Finnish ("Grandma has *viisi*
  buns"). `src/components/math/noDigits.test.tsx` renders every math screen,
  taps every word, and fails on a digit, a number picture or an English number
  word. A glossary gloss for a math word avoids number words too ("which of
  them has", not "which one has").
- **Choices:** the answer and its near misses, as many as the level asks for —
  at the ends too (*kymmenen* and *sata* get tens from one side only). The
  clock's slips are the ones that teach: the time it is now, an hour the other
  way, and (half past) *puoli* with the hour it is now.
- **Levels:** three choices, then four; from level 3 a problem is only heard
  (its words on *Lue*); at the top the choices are only heard too. Saying the
  answer (`matchNumberSpeech`: "viis" is *viisi*, but *kolmetoista* is never
  *kolme*, and *puoli neljä* is never *neljä*; `matchAnswerSpeech` hears a half
  hour as *puoli* and its hour, so "puoli yksitoista" is never *puoli yksi*; a
  time the recognizer writes in digits, "3.30", reads as *puoli neljä*) and
  typing it are bonus rounds.
- **When math runs out:** the shop and the clock wait on course units, so a
  child can win every open crown and still have stages ahead. The map, the
  home card and a crown's result then name the stage ahead and the unit it
  waits for (`stageAhead`), never "every crown won".
- **A math lesson** uses the math examples (`{ sum }`, `{ which }`, `{ next }`,
  `{ teen }`, `{ n }`, `{ problem }`, `{ tens }`, `{ times }`, `{ half }`,
  `{ price }`, `{ total }`, `{ clock }`, `{ clockMove }` in `lessons.ts`): a
  frame filled with sourced numbers, shown with dots (a clock time with its
  face). Its prose must not name a number in English.
- **Today's sums** (`/math/today`, *Päivän laskut*): once a day, a problem from
  each of a few games of the stages begun (not the train, the builder or quick
  sums), only heard, for bonus stars; the days in a row show as flames.
  `todayPlan` and friends are in `mathCourse.ts`.
- **Badges and faces:** the *Lasketaan!* group in `src/game/badges.ts` measures
  the math record only (`FIRST_MATH_STAGES` keeps "every crown" fixed). Their
  titles can show on a math screen, so no digit or English number word. Three
  win a face (`src/game/faces.ts`), put on from Achievements; the child's own
  animal is kept to go back to.
- **A math story** (`src/content/mathStories.ts`) follows the story rules, and
  keeps numbers in Finnish in its English too.

## The Alphabet & sounds corner (optional)

`/sounds` — never part of the course; nothing there unlocks or blocks a unit.

- `src/content/alphabet.ts`: the 29 letters (Finnish letter NAME, a kid-level
  sound tip, borrowed / vowel flags) and the "tricky sounds" guides. Example
  words are listed by their Finnish spelling and must exist in the sourced
  data (`alphabet.test.ts`); letter names are authored and listed for review.
- Letter NAMES are taught first: every tile shows its name (J / *jii*), the
  letter card leads with it, "Listen to the whole alphabet" reads them in order,
  and the *Kirjainten nimet* game alternates hear-the-name → tap the letter and
  see-the-letter → pick its name (sound-alike names as wrong options).
- `src/game/soundGames.ts`: three listening games over real sourced words
  with a gap — the options are only LETTERS (*a / ä*, *s / ss*), so no made-up
  word is ever shown. Results are stored in `course.sounds`, apart from the
  course; the "Sound explorer" achievement asks for all four games.
